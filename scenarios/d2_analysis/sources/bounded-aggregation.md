# 用量波动的最小聚合与防截断

维护范围：`core_product_operations`。本方法补充执行策略，不替代各资源指标 definition、SQL、数据源字段与单位，不提升知识审核状态。

## 先固定范围，再选择执行计划

1. 按指标 ID 读取原始本体，探测真实字段和最新 `MAX(p_date)`；日分区覆盖两个窗口，全量收入/映射表只固定一个物理分区，再筛业务日期。各次查询传入同一批冻结参数。
2. 默认比较相邻30日。EIP不提供用量波动；VKE按其实际截止日计算窗口。窗口缺日时暂停该指标环比和Top5，不能把漏数补零。
3. CPU/GPU使用物理“计费方式”，不要拿 `pay_type` 替代。保留所有计费方式做总盘对账；包年包月与按量计费分别展示正负Top5。`包年包月（包含OPPO）`仅展示简称可改成“包年包月”。稳定ID参与关联，名称只展示。
4. 存储强制应用本体的计费元素过滤。接口不便表达LIKE时，可先在相同产品和完整两期窗口枚举全部低基数元素，按原规则筛出完整IN列表并冻结。不能先返回客户×日期×元素再本地过滤。
5. 数据库CPU与内存独立；CPU排除Redis并保留合法空product_name，内存仅Redis。VKE不得擅增资源大于0等本体没有的过滤。

## 两条等价路径

优先使用已验证支持的源端SQL：先聚合两期稳定客户键，完整外连接，算差值，在源端按差值排序取正负Top5；产品整体两期总量另查。确认SQL是在完整候选集合上排序后LIMIT，不能先LIMIT两期再做差。

2026-10-20实测可用的最小路径是：先由同口径VQS取得真实物理表、字段表达式和WHERE，再对两个互斥窗口`UNION ALL`，按稳定ID和必要计费分组做`sumIf`条件聚合；两侧都先`ifNull(...,0)`，随后计算delta并用窗口排名返回正负Top6。缺侧若不先置0，`current-previous`会成为NULL，`sum`会忽略单边客户并产生错误总差；不能只在最终展示层补0。物理表名不能用dataset ID代替，也不能从历史schema猜测。

生成SQL中的记录级条件可能被VQS放在HAVING。仅当指标定义证明它是原始记录过滤，并且移动到WHERE后与独立VQS总量对账通过，才能适配；真正的聚合阈值继续留在HAVING。本次SQL接口对29个最终查询均返回`truncated=false`，每个用量产品的两期SUM均与独立VQS统计在容差内一致。只有完成这类对账，才可用SQL小结果替代客户聚合行导出。

结构化接口无法表达外连接/条件聚合时，使用客户×周期最小聚合：

- 对每产品、周期、必要计费方式，先查客户去重数、键范围、日期数与总量。日期完整且每日口径一致时，`SUM(周期用量)/30`与“每日总量再取30日均值”等价，返回时不必携带客户日明细。
- 返回字段限稳定键、必要计费方式、`SUM(用量)`。不返回实例、地域、规格、账单、计费元素等非必需维度。
- 单批基数小于阈值才执行。较大集合按稳定ID互斥区间递归拆分，子范围分别计数；两子范围人数和金额必须等于父范围。根据实际字段类型选择数值或字典序边界。
- 返回上限预留检测余量（本次实例基数阈值8000，limit8001，并非平台保证）。每批实际唯一键数须匹配同范围独立计数，全部叶子区间不重叠且覆盖父范围，总量对账通过后才能合并。
- 不支持真实分页令牌的接口，不自行编造offset/page_token。返回达到limit、存在partial/truncated/has_more、字段缺失或计数不符时，均视为未完成；不能本地去重后假称完整。

完整两期集合按稳定键外连接。仅在源窗口完整、数值非空、全部批次完整且总量一致的前提下，将缺侧解释为该范围无事实并赋0；对缺分区、缺结果、非法空数值不补0。日均分母固定为完整周期日数，不能对每个客户仅有记录的日期求均值。

在未舍入差值上排序，以稳定ID打破并列；取每批正负Top6并保留边界，可合并复核全局Top5。完整客户差值与独立总盘差值对账，计费方式贡献互斥，保留Top5外残差。核/卡按原始单位核验，展示才换万核/万卡；容量按指标规定换PiB/TiB/GiB。

## VQS返回层实测问题

2026-10-19使用aeolus-openapi-query的结构化入口时发现：SQL包含同一字段的uniq/min/max，但默认schema.measures的uniqueId都等于原始字段ID，vizData.datasets以原始字段ID为键，前两个结果被最后值覆盖。只看SQL成功会漏掉此错误。

本次仅在任务适配层将每个measure.uniqueId设置为其聚合选择ID（如 `uniq_<field_id>`、`min_<field_id>`、`max_<field_id>`），保持原始dimMetId、originId不变；实测返回了全部独立聚合键。每次执行前后仍必须验证预期输出字段集合，不能把此经验视为对所有版本的保证。也可拆开查询同字段的不同聚合。

保存参数、生成VQS、真实返回SQL（若提供）、查询时间、queryHistoryId、每批行数、字段集合和工具计算SHA-256。响应的isPartialData与其他截断信号均需检查。接口请求频率限制与结果行数截断是两个问题；本次最短请求间隔调整为6.2秒后继续，遵守有限重试，不无限重发。
