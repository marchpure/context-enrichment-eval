# 场景 C：研发上下文补丁（`DEV-01` ~ `DEV-12`）

- 题库拆分：`DEV-01..08`（`dev`），`DEV-09..12`（`holdout`）。
- 验收方式：在合成代码仓上生成真实补丁并运行目标单测 + 全量回归单测，同时验证 `APPROVED` vs `REJECTED`/`DRAFT` 决策保真与零新回归。
- `repository/` 是第六轮 Cedar 合成仓的代码和契约。模型只读冻结树，验收器把改动应用到临时副本。每次用断网、只读挂载的 Python 容器运行目标与回归单测。
- 目标测试沿用归档。回归补上成功 POST 无额外尝试、无效 429 Retry-After 无额外等待。`scoring/` 中的参考修复仅用于证明测试区分度。
